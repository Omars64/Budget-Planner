# Operational policy backend contract

Policy GET/PUT remains `/api/admin/resource-policy`, with `{policy, revision, coordination, status}` responses. PUT requires the existing three integer fields: client_poll_seconds, idle_recheck_minutes, database_probe_minutes. Omitted scheduler and new fields preserve the current values inside the revision CAS. Unknown fields, booleans supplied as integers, and out-of-range values are rejected. Stale revision returns 409; unconfirmed storage returns 503 and must not be represented as a successful save.

New defaults: client_idle_minutes=30; ai_global_daily_requests=50; ai_user_daily_requests=50; ai_global_minute_requests=15; ai_max_output_tokens=1800; release_notifications_enabled=true; scheduled_notifications_enabled=true; upcoming_notifications_enabled=true; notification_batch_size=5; backup_interval_hours=24; backup_skip_unchanged=false. These are operational settings; this change performs no financial migration or backup/AI execution changes.

`GET /api/runtime-policy` returns `{client_poll_seconds, client_idle_minutes}` without database initialization, including default fallback when coordination is unavailable.

Admin-only `GET /api/admin/resource-policy/history?limit=100` accepts limits 1..100 and returns `{items: [...]}` newest first. Each event has actor_id (string user ID), at (Unix seconds from Redis TIME), changes (field -> {before, after}). Successful saves, including no-op saves with empty changes, produce events. Conflict produces none. Retention is 100. Policy, revision, and bounded audit JSON are written in a single MSET within the existing Lua CAS. Corrupt audit prevents saving. Transport ambiguity still returns 503: reload state before retrying. No emails, financial records, or credentials are stored.

`control.record_metric(name, value=1)` returns True when confirmed, False on coordination unavailability; callers must not fail successful manual work based on False. Invalid names or non-integer increments outside 1..1000000 raise ValueError. Exact allowlist: ai_attempts, ai_successes, ai_fallbacks, ai_input_tokens, ai_output_tokens, backup_upload_runs, backup_unchanged_runs, backup_interval_skips, notification_sent, notification_failed, notification_paused. The atomic aggregate counters saturate at 1000000000000, have no labels/user IDs/payloads, and use a fixed set of keys. No financial data belongs in Redis.

Admin-only `GET /api/admin/resource-metrics` (also aliased at `/api/admin/resource-policy/metrics`) returns `{metrics: {counter_name: total}, since: enabled_at, reset_at}`. enabled_at is the Redis Unix timestamp of the first recorded metric; reset_at is null (no reset endpoint). Before recording, enabled_at is null and counters is empty. These are totals since enablement, not daily usage limits or money. `control.read_metrics()` returns `{enabled_at, reset_at, counters}`. History `at` and metrics `since` use Unix epoch seconds, not ISO strings. Read failures return 503, never fabricated zero totals.

Focused verification: `python -m pytest --noconftest tests/test_resource_control.py`; `python -m pytest tests/test_resource_runtime.py`. Lua tests use fakeredis/lupa in memory with synthetic credentials and blocked network calls.

## Runtime enforcement and safety

The integrated controls are available under Admin → Database usage. Presets edit a draft only; the existing revision-protected Save applies it. Balanced and Responsive change timing without resetting AI quotas or notification preferences. Economy can reduce AI ceilings but never increases an existing ceiling or re-enables a disabled service. Use safe defaults is an explicit full policy reset followed by Save. Settings apply to new work; an already-running request may finish.

AI uses the existing atomic database-backed rate buckets for shared daily/minute and per-user daily reservations. Daily windows are 24 hours from each bucket's start, not a calendar-midnight reset. A zero daily ceiling prevents paid calls while built-in guidance remains available. Chat, draft extraction and connection checks share the global allowance. Token caps limit output, not total invoice cost. Configured coordination outages fail closed for paid AI and server notification delivery. Provider credentials remain environment secrets; the dashboard cannot reveal or replace them.

Hidden/offline clients already pause background reads. The public idle setting now controls visible inactivity from 5–60 minutes; interaction resumes reads. This does not sign users out or block manual saves. Metrics and audit history refresh only on administrator request, avoiding extra polling. Counters are aggregate totals since tracking began, not provider billing or complete database-call accounting. Security/account history remains separate from operational policy history.

Notification gates affect server delivery of release alerts, scheduled-entry confirmations and browser upcoming reminders. Native local phone reminders remain independent and device opt-ins remain authoritative. Scheduled outbox work is preserved while delivery is paused; existing expiry rules still apply. Batch size bounds scheduled delivery and query fetch chunks; release delivery retains its existing per-platform budget, and due reminders are not deliberately delayed to fill a batch.

Automatic external backups use a minimum 6–24 hour spacing with five minutes of cron jitter tolerance. The existing daily trigger still determines actual cadence; this setting does not create more frequent cron jobs. A failed last run is retried, and manual Run recovery and backup bypasses interval and duplicate checks. In-database recovery snapshots and their existing retention are unchanged.

Optional unchanged-upload optimization exports current records and identity metadata, fingerprints everything except the export timestamp, then authenticates the prior complete encrypted run and recomputes its content fingerprint. Missing/corrupt/different data always causes a fresh upload. A fresh full copy is forced at least every seven days when the automatic job runs. Backup freshness is refreshed only after upload read-back or verified unchanged content. Staging files contain ciphertext only and are temporary. The encrypted optimization pointer is under the same private bucket prefix; no plaintext account data is placed in Redis. No off-site backup copies are deleted. This optimization saves redundant uploads, not the database reads needed to establish unchanged content.
